# Hestia — สเปก v1

> สถานะ: ร่าง (2026-10-25) · สรุปจากการคุยไล่ฟีเจอร์ 3 รอบ
> ข้อที่ระบุว่า **[ค่าเริ่มต้น]** คือข้อที่ยังไม่ได้ยืนยัน ใช้ตามที่แนะนำไว้ก่อน

## 1. ภาพรวม

Hestia เป็นระบบ SaaS แบบ multi-tenant สำหรับเจ้าของที่พักให้เช่า**รายเดือน** รองรับทั้งบ้านเช่าแบบล็อก (ชั้นเดียว หลายห้องติดกัน) และอาคารหลายชั้น เช่น อพาร์ทเม้นท์และหอพัก รวมถึงโครงการที่มีทั้งสองแบบปนกัน เจ้าของหลายรายสมัครใช้ได้ โดยข้อมูลของแต่ละองค์กร (org) แยกขาดจากกัน

**ผู้ใช้ระบบ:** มีแค่ทีมของเจ้าของเท่านั้น (owner / manager / staff) ผู้เช่าไม่ต้องล็อกอินและไม่มีแอป ผู้เช่าเห็นระบบผ่าน**ลิงก์บิลสาธารณะ**อย่างเดียว

## 2. ขอบเขต

### MVP
- Org → โครงการ (property) → อาคาร/แถว (building) → ชั้น (floor) → ห้อง (unit)
  - บ้านเช่าแบบล็อก: 1 แถว = 1 building ที่มีชั้นเดียว
  - อพาร์ทเม้นท์: 1 อาคาร = 1 building ที่มีหลายชั้น
  - โครงการเล็กที่ไม่ต้องแบ่งอาคาร ระบบสร้าง building ตั้งต้นให้ 1 อัน และซ่อนไว้ใน UI
  - สร้างห้องทีละหลายห้องได้ เช่น ชั้น 2–5 ชั้นละ 10 ห้อง ให้รหัสห้องเป็น `{ชั้น}{ลำดับ}` → 201…510
- ผู้เช่าทั้งบุคคลธรรมดาและนิติบุคคล สัญญา 1 ฉบับมีผู้ชำระ 1 คน คนอื่นเป็นผู้อยู่ร่วม
- วงจรสัญญา: จอง + มัดจำจอง → ย้ายเข้า → ต่อสัญญาอัตโนมัติ → ย้ายออก
- จดมิเตอร์น้ำและไฟผ่านมือถือ (เว็บ responsive) พร้อมแนบรูป
- ออกบิลรายเดือน คิด pro-rate เดือนแรกและเดือนสุดท้าย รองรับค่าใช้จ่ายเพิ่มเติมทั้งแบบครั้งเดียวและแบบประจำ
- Dynamic PromptPay QR ที่ฝังยอดเงิน
- ชำระเงิน: ผู้จัดการกดยืนยันเอง หรือผู้เช่าแนบสลิปแล้วระบบตรวจสลิปอัตโนมัติ
- ค่าปรับรายวันหลังพ้น grace period · จ่ายเกินเก็บเป็นเครดิต
- VAT รายรายการ, หัก ณ ที่จ่าย 5%, ใบกำกับภาษีแบบ PDF ที่แก้ไขไม่ได้, ใบลดหนี้และใบเพิ่มหนี้
- แจ้งซ่อม (staff เป็นคนสร้าง ticket) · การแจ้งเตือนภายในระบบ
- รายงาน + export Excel · import ข้อมูลจาก Excel
- RBAC กำหนดสิทธิ์รายโครงการ + audit log
- คิดเงินลูกค้า SaaS: แบบ tier, ทดลองใช้ฟรี 1 เดือน, ผ่าน Omise, ค้างจ่ายแล้วระบบเป็นโหมดอ่านอย่างเดียว
- ภาษาไทยอย่างเดียว เอกสารแสดงปี พ.ศ.

### Phase 2 ขึ้นไป
- LINE OA ของแต่ละ org: ส่งบิล แจ้งเตือนผู้เช่า รับสลิปทางแชท
- e-Tax Invoice
- QR แบบ merchant ของธนาคารที่มี callback (KBank, SCB)
- ค่าน้ำค่าไฟแบบอัตราขั้นบันได
- การเช่ารายวัน (ระบบจองตามปฏิทิน)
- หลายภาษา · PWA และการใช้งานออฟไลน์

## 3. สถาปัตยกรรม

```
hestia/                      (Bun workspaces + Turborepo)
├── apps/
│   ├── web/                 Next.js 16 + shadcn — แอปของทีม + หน้าบิลสาธารณะ /b/[token]
│   └── api/                 Elysia — REST API, งานตามรอบเวลา (ค่าปรับ, ต่อสัญญา)
├── packages/
│   ├── db/                  Drizzle schema, migration, seed
│   ├── ui/                  shadcn components (มีอยู่แล้ว)
│   ├── shared/              zod schema, ค่าคงที่, ฟังก์ชันเงิน/วันที่/PromptPay
│   ├── eslint-config/
│   └── typescript-config/
└── docker-compose.yml       Postgres + MinIO สำหรับรันบนเครื่อง
```

- **web → api:** เรียกแบบ type-safe ผ่าน Eden Treaty
- **Auth:** Better Auth (ใช้ Drizzle adapter + organization plugin) ติดตั้งที่ api
- **ไฟล์:** MinIO ตอนรันบนเครื่อง แล้วเปลี่ยนเป็น S3 หรือ R2 ตอนขึ้นจริง แยก bucket ไว้ 2 ชุด
  - `files` สำหรับสลิป รูปมิเตอร์ และรูปงานซ่อม
  - `pii` สำหรับสำเนาบัตรประชาชน ให้ดูได้แค่ owner และ manager และบันทึก log ทุกครั้งที่เปิดดู
- **PDF:** สร้างที่ฝั่ง api (เลือก library ตอนทำ phase 4)

### การแยกข้อมูลระหว่าง org (2 ชั้น)
1. ทุกตารางธุรกิจมี `org_id` และ repository layer บังคับ filter ทุก query
2. เปิด **Postgres RLS** กับทุกตารางที่มี `org_id` โดย api ตั้งค่า `SET LOCAL app.org_id = …` ในทุก transaction และ role ของแอปต้องไม่มีสิทธิ์ `BYPASSRLS`

## 4. RBAC

Role มี 3 แบบตายตัว ผู้ใช้หนึ่งคนอยู่ได้หลาย org ส่วน manager และ staff เห็นเฉพาะโครงการที่ได้รับมอบหมาย

| การกระทำ | owner | manager | staff |
|---|:-:|:-:|:-:|
| ตั้งค่า org, ภาษี, PromptPay, แพ็กเกจ SaaS | ✅ | – | – |
| จัดการผู้ใช้และกำหนดโครงการให้ | ✅ | – | – |
| สร้างหรือแก้โครงการและห้อง | ✅ | ✅ | – |
| ผู้เช่าและสัญญา (สร้าง/ต่อ/ยกเลิก) | ✅ | ✅ | สร้างร่าง |
| ดูสำเนาบัตรประชาชน | ✅ | ✅ | – |
| จดมิเตอร์ | ✅ | ✅ | ✅ |
| ออกบิล | ✅ | ✅ | – |
| ยืนยันการชำระ / ตรวจคิวสลิป | ✅ | ✅ | ✅ |
| ยกเว้นค่าปรับ, ออกใบลดหนี้/เพิ่มหนี้, void บิล | ✅ | ✅ | – |
| แจ้งซ่อม | ✅ | ✅ | ✅ |
| รายงานการเงิน | ✅ | ✅ | – |
| ดู audit log | ✅ | – | – |

## 5. Data model (ตารางหลัก)

หลักการ:
- **เงิน**เก็บเป็นจำนวนเต็มหน่วย**สตางค์** (`bigint`) ห้ามใช้ float
- **วันที่**เก็บเป็น ค.ศ. (`date` และ `timestamptz`) แล้วค่อยแปลงเป็น พ.ศ. ตอนแสดงผล
- ทุกตารางมี `id` (uuid v7), `created_at`, `updated_at` · ตารางธุรกิจมี `org_id`

**องค์กรและผู้ใช้**
- `organizations`: ชื่อ, เลขผู้เสียภาษี, รหัสสาขา, จด VAT ไหม, ที่อยู่, PromptPay ID, `settings` (grace_days, late_fee_per_day, late_fee_cap, booking_expiry_days, booking_forfeit_on_cancel)
- `users`, `sessions`, `accounts`: ตารางของ Better Auth
- `memberships`: org_id, user_id, role
- `membership_properties`: membership_id, property_id (ใช้กำหนดขอบเขตของ manager และ staff)

**สินทรัพย์**
- `properties`: ชื่อ, ประเภท (`row_house` | `apartment` | `mixed`, ใช้เลือกคำเรียกและค่าเริ่มต้นใน UI), ที่อยู่, วันออกบิล, วันครบกำหนด, วันจดมิเตอร์
- `buildings`: property_id, ชื่อ (เช่น "อาคาร A" หรือ "แถว 1"), จำนวนชั้น, ลำดับการแสดง
- `units`: building_id, ชั้น (`floor`, ค่าเริ่มต้น 1), รหัสห้อง (unique ภายใน property), ประเภทห้อง (เช่น สตูดิโอ, 1 ห้องนอน, บ้านทั้งล็อก), ขนาดพื้นที่, ค่าเช่าตั้งต้น, สถานะ (`vacant` | `reserved` | `occupied` | `maintenance`)
  - เก็บ `property_id` ซ้ำไว้ที่ห้องด้วย เพื่อให้ query และ RLS ง่าย
- `unit_utilities`: unit_id, ประเภท (`water` | `electric`), โหมด (`submeter` | `direct` คือผู้เช่าจ่ายการไฟฟ้า/ประปาเอง | `flat` คือเหมาจ่าย), ราคาต่อหน่วย, ค่าขั้นต่ำ, ยอดเหมา
- `meters`: unit_id, ประเภท, หมายเลขมิเตอร์, เลขเริ่มต้น, วันติดตั้ง, วันถอด (การเปลี่ยนมิเตอร์ = ถอดตัวเก่าแล้วติดตั้งตัวใหม่)
- `meter_readings`: meter_id, รอบบิล, เลขที่อ่านได้, รูป, คนจด, เวลาจด

**ผู้เช่าและสัญญา**
- `tenants`: ประเภท (`person` | `juristic`), ชื่อ, เลขบัตร/เลขผู้เสียภาษี (เข้ารหัส), โทรศัพท์, LINE ID, ที่อยู่สำหรับออกใบกำกับ
- `tenant_documents`: tenant_id, ประเภท, file_key (อยู่ใน bucket `pii`), เวลาที่ให้ consent, เก็บถึงวันไหน
- `contracts`: unit_id, payer_tenant_id, สถานะ (`reserved` | `active` | `ended` | `cancelled`), วันเริ่ม, วันสิ้นสุด, ค่าเช่า, เงินประกัน, มัดจำจอง, วันหมดอายุการจอง, ต่ออัตโนมัติไหม, `renewed_from_id`
- `contract_occupants`: contract_id, tenant_id
- `charge_types`: ชื่อ, ประเภท VAT (`exempt` | `exclusive` | `inclusive`), อัตรา VAT, หัก ณ ที่จ่ายได้ไหม
- `contract_charges`: contract_id, charge_type_id, ยอด, รูปแบบ (`recurring` | `once`), เดือนที่มีผล

**การเงิน**
- `invoices` (ใบแจ้งหนี้): contract_id, รอบบิล, เลขที่, วันออก, วันครบกำหนด, สถานะ (`draft` | `issued` | `partial` | `paid` | `void`), ยอดก่อน VAT, VAT, ยอดรวม, `public_token`
- `invoice_lines`: invoice_id, charge_type_id, คำอธิบาย, จำนวน, ราคาต่อหน่วย, ยอด, VAT, อ้างอิงเลขมิเตอร์ (ถ้ามี)
- `payments`: contract_id, ยอด, ยอดหัก ณ ที่จ่าย, วิธีชำระ, วันที่จ่าย, สถานะ (`pending_review` | `confirmed` | `rejected`), slip_key, ผลตรวจสลิป (jsonb), `slip_ref` (unique กันใช้สลิปซ้ำ)
- `payment_allocations`: payment_id, invoice_id, ยอด
- `ledger_entries`: บัญชีของสัญญา (charge, payment, credit, late_fee, waiver, deposit_in, deposit_refund, deposit_deduct) เก็บยอดแบบมีเครื่องหมายบวกลบ และ**ห้ามแก้หรือลบ**แถวที่บันทึกแล้ว
- `tax_documents`: ประเภท (`receipt` | `tax_invoice` | `credit_note` | `debit_note`), เลขที่, อ้างอิงเอกสาร, snapshot ข้อมูลผู้ซื้อและผู้ขาย, pdf_key · **แก้ไขไม่ได้**
- `document_sequences`: org_id, ประเภทเอกสาร, ปี, เลขล่าสุด (ล็อกแถวตอนออกเลข)

**ปฏิบัติการ**
- `maintenance_tickets`: unit_id, รายละเอียด, รูป, ผู้รับผิดชอบ, สถานะ, ค่าซ่อม, คิดเงินใคร (`tenant` | `owner`)
- `notifications`: user_id, ประเภท, payload, อ่านแล้วเมื่อไร
- `audit_logs`: org_id, actor_id, action, entity, entity_id, ข้อมูลก่อน/หลัง, ip, เวลา
- `pii_access_logs`: ใครเปิดดูเอกสารไหน เมื่อไร
- `import_jobs`: ไฟล์, ประเภท, สถานะ, รายการ error ทีละแถว

**SaaS**
- `plans`: tier, จำนวนห้องสูงสุด, ราคา
- `subscriptions`: org_id, plan_id, สถานะ (`trialing` | `active` | `past_due` | `read_only`), วันหมดทดลองใช้, รหัสลูกค้า Omise
- `subscription_invoices`: ใบแจ้งหนี้ที่ Hestia เรียกเก็บจาก org

## 6. Flow หลัก

### 6.1 รอบบิลรายเดือน
1. **วันจดมิเตอร์:** ระบบเตือน staff → staff เปิดรายการห้องบนมือถือ (เรียงตามอาคาร → ชั้น → ห้อง ตามลำดับที่เดินจดจริง) กรอกเลขมิเตอร์และถ่ายรูป
   ระบบเตือนเมื่อเลขที่จดน้อยกว่าครั้งก่อน หรือหน่วยที่ใช้สูงผิดปกติ
2. **สร้างร่างบิล** ของทั้งโครงการ ประกอบด้วย ค่าเช่า (pro-rate ถ้าเป็นเดือนแรกหรือเดือนสุดท้าย), ค่าน้ำค่าไฟตามโหมดของห้อง, ค่าใช้จ่ายเพิ่มเติม, ค่าปรับค้างจากรอบก่อน, และหักเครดิตที่มีอยู่
3. **manager ตรวจแล้วกดออกบิล:** บิลได้เลขที่และแก้ไขไม่ได้อีก ถ้าต้องแก้ต้อง void แล้วออกใหม่ หรือออกใบลดหนี้/เพิ่มหนี้
4. **ส่งบิล:** กด "แชร์" ได้รูปบิลพร้อม QR และลิงก์ `/b/{token}` แล้วส่งเข้า LINE ส่วนตัว **[ค่าเริ่มต้น]**

### 6.2 การชำระเงิน
- **หน้าบิลสาธารณะ** `/b/{token}` (ไม่ต้องล็อกอิน) แสดงรายละเอียดบิล, PromptPay QR (EMVCo ฝังยอดคงค้าง), และปุ่มแนบสลิป **[ค่าเริ่มต้น]**
  token เดาไม่ได้ (128 bit) ยกเลิกได้ และไม่แสดงข้อมูลส่วนตัวเกินจำเป็น
- **เมื่อแนบสลิป:** ส่งสลิปไปตรวจด้วย API (SlipOK หรือ EasySlip)
  - ผ่านทุกเงื่อนไข (ยอดตรง, บัญชีผู้รับตรงกับ org, `slip_ref` ไม่ซ้ำ) → ยืนยันอัตโนมัติ
  - ไม่ผ่านหรือยอดไม่ตรง → เข้าคิว "รอตรวจ"
- **ยืนยันเอง:** staff ขึ้นไปบันทึกการรับเงิน (โอน หรือเงินสด) ได้
- **ตัดชำระ:** ชำระบิลที่เก่าที่สุดก่อน ส่วนที่เกินเข้าเป็นเครดิตของสัญญา
- **ผู้เช่านิติบุคคล:** บันทึกยอดหัก ณ ที่จ่าย 5% แยกไว้ และแนบหนังสือรับรองการหักภาษี ณ ที่จ่าย (50 ทวิ)
- **หลังรับเงิน:** ออกใบเสร็จ (และใบกำกับภาษีถ้า org จด VAT) เป็น PDF

### 6.3 ค่าปรับ **[ค่าเริ่มต้น]**
- งานรายวันคิดค่าปรับ = อัตราต่อวัน × จำนวนวันที่เลยวันครบกำหนดเกิน grace_days จำกัดไม่เกินเพดาน (ถ้าตั้งไว้)
- ค่าปรับสะสมเป็น 1 รายการต่อบิล และไปปรากฏในบิลรอบถัดไป
- manager ขึ้นไปยกเว้นค่าปรับได้ โดยต้องใส่เหตุผลและระบบบันทึก audit

### 6.4 วงจรสัญญา
- **จอง:** สร้างสัญญาสถานะ `reserved` รับมัดจำจอง และตั้งวันหมดอายุ ห้องเปลี่ยนเป็น `reserved`
  ถ้าเลยวันหมดอายุหรือยกเลิก มัดจำจะถูกริบเป็นค่าเริ่มต้น (org เปลี่ยนได้) **[ค่าเริ่มต้น]**
- **ย้ายเข้า:** เปลี่ยนเป็น `active` รับเงินประกัน (มัดจำจองแปลงเป็นส่วนหนึ่งของเงินประกัน) จดเลขมิเตอร์เริ่มต้น บิลแรกคิด pro-rate
- **ต่อสัญญา:** ถ้าเปิดต่ออัตโนมัติ ระบบสร้างสัญญาใหม่ที่อ้าง `renewed_from_id`
  ปรับค่าเช่าได้**เฉพาะตอนต่อสัญญา** และต้องแจ้งผู้เช่าล่วงหน้าอย่างน้อย 1 เดือน ระบบเตือนทีมก่อนครบกำหนด
- **ย้ายออก:** จดมิเตอร์ครั้งสุดท้าย → บิลสุดท้ายคิด pro-rate → หักค่าเสียหายและยอดค้างจากเงินประกัน → คืนส่วนที่เหลือหรือเรียกเก็บเพิ่ม → ห้องกลับเป็น `vacant`

### 6.5 แจ้งซ่อม
ผู้เช่าแจ้ง staff ทางช่องทางไหนก็ได้ → staff สร้าง ticket พร้อมรูป → มอบหมายผู้รับผิดชอบ → ปิดงาน ถ้าคิดเงินผู้เช่า ค่าซ่อมจะเข้าบิลรอบถัดไป

## 7. ภาษี

- ค่าเช่าอสังหาริมทรัพย์ได้รับยกเว้น VAT แต่บริการอื่น (เช่น ค่าน้ำค่าไฟที่เรียกเก็บต่อ ค่าเฟอร์นิเจอร์ ค่าบริการ) อาจต้องคิด VAT จึงตั้งค่า VAT แยกตาม `charge_types` **(ควรยืนยันกับนักบัญชี)**
- ใบกำกับภาษีออก ณ วันที่รับชำระ (จุดความรับผิดของบริการ) และแก้ไขไม่ได้ ถ้าต้องแก้ใช้ใบลดหนี้หรือใบเพิ่มหนี้
- เลขที่เอกสารรันแยกตาม org × ประเภท × ปี และไม่มีเลขขาดช่วง
- เอกสารเก็บ snapshot ชื่อ ที่อยู่ และเลขผู้เสียภาษี ณ วันที่ออก

## 8. SaaS
- สมัครแล้วได้ทดลองใช้ฟรี 1 เดือน · ราคาแบบ tier ตามจำนวนห้อง · ตัดบัตรผ่าน Omise
- ค้างจ่ายแล้วสถานะเป็น `past_due` (มีช่วงผ่อนผัน) แล้วจึงเป็น `read_only` ซึ่งยังดูและ export ข้อมูลได้ แต่สร้างหรือแก้ข้อมูลไม่ได้ ระบบบังคับที่ middleware ของ api

## 9. Import จาก Excel
- มี template ให้ 3 แบบ: ห้อง, ผู้เช่า + สัญญา, ยอดค้างยกมา
- ขั้นตอน: upload → ตรวจทีละแถวและแสดง error → ยืนยัน → import ใน transaction เดียว
- ยอดค้างยกมาบันทึกเป็น ledger entry ประเภท `opening_balance`

## 10. ข้อกำหนดอื่น
- **PDPA:** ขอ consent ก่อนเก็บสำเนาบัตร กำหนดระยะเวลาเก็บ (เช่น สัญญาจบแล้ว + N ปี) และมีงานลบอัตโนมัติ เลขบัตรเข้ารหัสระดับ column
- **Audit log:** บันทึกทุกการเปลี่ยนแปลงเรื่องเงิน สัญญา สิทธิ์ผู้ใช้ และการตั้งค่า
- **ฟอร์แมต:** แสดงวันที่เป็น พ.ศ. · เงินใช้รูปแบบ `฿1,234.50`
- **มือถือ:** หน้าจดมิเตอร์และหน้าบิลสาธารณะต้องออกแบบโดยคิดถึงมือถือก่อน
